# Study Reports
## User Test 1
### Summary
Most of the user test tasks ran very smoothly with only a few minor inconveniences. I would describe our interface setting up the application very intuitive as there were no issues for the user in terms of finding any certain page. The user also described our application as very similar in structure to other review apps like letterboxd. The first issue arose though when the user was prompted to personalize their profile with a picture. The process to upload the image was simple but there was a minor bug with the first image not displaying correctly. This could be due to various reasons but requires more testing as this feature is very dependent on the user. The following tasks were very easy to follow and it was simple to navigate between the main features of the apps like the playlists, feed, and song pages. The only note is that throughout the experience there was a bit of lag when loading pages like the feed and reviews. The user mentioned this was an inconvenience but did not ultimately affect the core usability of the app. There were no further issues navigating the main features of the application and the user gave many recommendations on possible new features to add. The last difficulty the user had came up when he was prompted to remove a song from the playlists. The way that the buttons were designed are a bit unintuitive as it is unclear from the song page whether or not the song is in the playlist. The user also used the profile page as the main way to access the features of the application which led to an issue with this task because there is no clear delete button on this view of the playlists. This revealed another way the user might interact with the app that we did not account for completely. In summary, the experience was very intuitive and easy to follow during the user test with just a few minor design choices that confused the user at times.
### Opportunities for Improvement
1. One area for improvement is the functionality of uploading the profile picture on the user's page. This process was smooth with our testing, but to handle the high amount of variability in terms of what sort of image you are able to upload, we need to polish it a bit more. Most of the changes in this feature could be completed with some simple user guidelines on what sort of images they’re allowed to upload.
2. Another flaw with our design was the wait times associated with some of the queries, like the feed and search system. During this test, the user said the wait times for some of the features were so long that he wasn’t sure whether or not his request was processed. With more and more users on this application, we need to work on scalability issues. This could be resolved with more efficient queries being set up, but more testing is necessary.
3. The user’s main problem with the design of the app was the unclear indication of whether or not a song was in a user’s playlist. This problem is not rooted in any functionality of the app, but more in an unclear feature design on our part. This user test revealed how the user chose to remove a song from a playlist and how this specific method was slightly unclear. This could simply be resolved by changing the indication of these buttons when the song is in the playlist.


## User Test 2
### Summary
The user first attempted to sign up through the login page, but easily found the sign up page through the error message. The user tried to upload a profile picture that was too large, and was confused why the profile picture was not updating. I had to explain that the file was too large and she uploaded a smaller file. When editing her bio, the user first tried to click on the bio message, but then quickly navigated to the “Add Bio” button. The user easily searched up friends and added friend requests. The posting of comments and searching up songs was very smooth. The user later noted that the search quality was one of the best parts of the app. The user was able to submit a review pretty easily, although there was some confusion as it was submitted because nothing in the editing review section changed once she submitted it. There was a little message in the corner that said the review was submitted, but the user verbally asked if it was submitted for assurance. She clicked around the text box, presumably because she expected the text to disappear once the review was submitted. She also asked if she could review something twice. The submit button did not update to update review, so she tried to submit again and an error message that said that user id had already submitted the review popped up. In the debrief, she said that this was the least smooth part of the app, especially with the user id in the error message. She was easily able to add and remove songs from the playlist. She was a bit unsure how to modify a review. At first, she tried to modify though clicking on the text of her review in the feed, but then she clicked on the reviews page. At this point, the update review button was showing and she was able to update her review. She was easily able to delete songs from her playlist. To get to her playlist, she navigated to her profile and clicked on the playlists displayed there.

### Opportunities for Improvement
1. There should be some change in the Listen Later icon when a song has been added to a user’s listen later playlist. With the favorites icon, the heart is filled in when the user adds it to their list, but the icon stays the same for Listen Later. The user was confused whether or not a song had been added to her list already when she was on the song page, and removed a song that she actually wanted on her list,
2. There should be clearer error messages for submitting a review. The submit review button should turn to update review once a review is submitted. I think this was a bug on our end. But the error message that appeared said that the user_id had already submitted a review. The user thought the user_id in the error message made the application look unprofessional and found the message confusing.
3. There should be some change to the UI once a review is submitted, perhaps a collapsible section to the song page that is only open when editing. The user was confused if her review was submitted or if she was still in editing mode. Right now, there is no difference in the UI between editing and view mode for the song/review page, which confuses the user.
